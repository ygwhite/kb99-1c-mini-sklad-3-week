# Практика производственного обмена

Эти модули содержат авторский код запуска и проверки практики в предоставленной демоконфигурации Ветис.cf. Они не являются самостоятельной конфигурацией и не заменяют модуль кб99.

Выполненный обмен находится в локальной базе `D:\PROGRAMING\PROJECTS\1C\bases\mercury-week3-production`. Её можно открыть ярлыком «Открыть Меркурий» в корне проекта. Запускайте только один сеанс этой базы: учебная платформа ограничивает число подключений.

Для воспроизведения с нуля:

1. Создайте отдельную пустую базу из предоставленного Ветис.cf.
2. В параметрах основной организации заполните учётные данные API, IssuerID и логин инициатора из Ветис Паспорта. Не добавляйте секреты в исходники или отчёт.
3. Убедитесь, что подключение использует `api2.vetrf.ru:8002`, затем загрузите сведения о хозяйствующем субъекте, нужной площадке, зарегистрированной продукции, её виде и единице измерения. Для учебной версии загружайте нужные записи, поскольку полный классификатор может превысить лимит.
4. Проверьте соответствие продукции и производственной площадки. В выполненной практике используется площадка `aec24873-ab51-4c3f-870f-01371347258a` и продукция `fc8dd0c8-e89b-46fa-af09-3055a68d3fed` — яйцо куриное свежее. Для неё выполнено первичное производство без исходного сырья.
5. Создайте документы ВСД2_Производство с отдельными номерами партий, количеством, единицей и датами. Отправьте заявки и получите результаты до COMPLETED.
6. Для каждой операции проверьте запись складского журнала и производственный ВСД. Успешной отправки заявки без результата недостаточно.

`ВыпуститьПятьПартий.bsl` использован как серверный общий модуль `ПрактикаНедели3` с экспортной функцией `НастроитьИПроверить`. В модуле управляемого приложения демобазы эта функция вызывается только при явном параметре запуска `/CWeek3Vetis`; затем протокол записывается в файл и приложение закрывается. Обычный запуск не отправляет документы.

Код предназначен для данной локальной практики: он содержит конкретные GUID, маркеры документов и пути файлов проверки. Перед переносом измените их. За один запуск обрабатывается одна новая операция; последующие запуски продолжают с первого неподтверждённого документа. В запуске используется ссылка справочника «Пользователи»; учётные записи платформы и права не меняются.

`SessionModule.demo.bsl` инициализирует ссылку пользователя для этой отдельной демобазы, в том числе при запуске без заданного пользователя платформы. `HTTPS.patch` показывает локальную доработку транспорта: явная Basic-аутентификация внутри проверяемого HTTPS, закрытие соединения после запроса и таймаут из параметров отправки вместо жёстких 120 секунд. Проверка сертификатов сохранена.

Повторный запуск пропускает COMPLETED, а при наличии ApplicationID получает ответ существующей заявки. Если ответ первоначальной отправки потерян, повторяется запрос по неизменённому документу с прежним localTransactionId. Это соответствует [назначению локального идентификатора в спецификации Ветис](https://help.vetrf.ru/images/d/d0/Application_management_service_requirements_1.1_v2.pdf): сервер исключает повторную обработку той же операции. Новый номер документа для такого повтора создавать нельзя.

`ПроверитьПятьПартий.bsl` выполняет отдельную проверку: пять COMPLETED-заявок, проведение документов, GUID/UUID каждой складской записи, UUID ВСД и количества 10, 20, 30, 40 и 50 шт. Проверяющий модуль читает результаты и не создаёт производственные заявки.

Разбор полей документа и фактические результаты приведены в [отчёте](../docs/week3/Отчёт.md). Предоставленный дистрибутив кб99, рабочая база и секреты остаются вне Git.
